# 小冶 (Xiaoye) M6 里程碑：应用层爆发与生产就绪规划

> **制定日期**: 2026-05-11
> **目标定位**: 基于 M5 全新四管线架构，实现多模态交互闭环、复杂科研图谱追踪与生产级多租户交付。

---

## 阶段一：科研沙盒与动态计算闭环 (Sandbox & Visualization)
**目标**：让小冶具备运行复杂物化计算代码的能力，并在前端直观展示执行过程与可视化结果。

### 后端改造
1. **沙盒安全与持久化**：
   - 强化 `src/tools/sandbox.py`，加入执行超时 (Timeout) 限制与基础的虚拟文件隔离限制。
   - 确保 Jupyter/IPython 内核状态在同一会话中跨轮次保持（如变量持久化）。
2. **多模态数据截获**：
   - 拦截 Python 产生的标准输出 (stdout)、错误流 (stderr) 及生成的图像（将 Matplotlib 输出转换为 Base64）。
   - 将沙盒执行事件转化为标准的 SSE 消息下发（例如 `type: "sandbox_execution", data: "..."`）。

### 前端改造
1. **对话栏代码块渲染**：
   - 在 `Notebook.tsx` 增加对应的组件，用于美观地渲染生成的代码块，并提供 "执行状态指示灯"（执行中、成功、报错）。
2. **Base64 图表内联展示**：
   - 当收到包含 Base64 图像的 Markdown 或特定的 SSE 图像事件时，支持在对话流中直接渲染生成的图表。
3. **右侧资源管理器**：
   - 增加一个 Tab 页，专门存放本会话所有执行生成的图表历史，方便学者比对数据。

---

## 阶段二：交互式知识图谱可视化 (Knowledge Graph UI)
**目标**：打破单纯文本的输出形式，用实体关系网直接回答冶金领域的网状问题（如“某元素的因果影响链路”）。

### 前端改造
1. **引入拓扑图引擎**：
   - 引入 `react-force-graph` 或 Apache `ECharts` 关系图模块。
2. **可视化面板**：
   - 在前端规划专属的图谱展现区域（可以设计为点击查阅时放大）。
   - 实现图谱节点的交互支持：点击节点高亮、悬浮展示属性等。

### 数据流对接
1. **Neo4j 响应格式化**：
   - 调整 `search_graph_relations` 工具的返回格式，支持返回规范的 Nodes 和 Edges JSON 给前端。
2. **科研工作流联动**：
   - 结合 M4 已有的 PDF 画框裁切功能，实现：`框选区域 → 抽取实体 → 触发图谱搜索 → 前端展示该实体的辐射网`。

---

## 阶段三：高级会话控制 (Fork Tree & Interrupt)
**目标**：提供专业级的信息流控制手段，解决长上下文容易污染的问题。

1. **树状 Fork UI 管理器**：
   - 重构右侧的 Fork 管理栏，由现在的列表（List）变为树状结构（Tree / Mindmap）。
   - 清晰标识出每一个分支的来源节点，并用视觉颜色（参考设计图中的说明）区分是否继承了主会话的全局记忆。
2. **强制打断机制 (Interrupt)**：
   - 在前端对话框旁增加一个明显的红色 **「停止/打断」** 按钮。
   - 对接后端：在 `Reasoning` 管线的 ReAct 循环中注入状态检查锚点，接收到打断指令时立刻终止 ToolNode/Evaluator 循环，避免陷入死循环消耗极高的 Token 成本。

---

## 阶段四：多租户隔离与生产发布 (Production Ready)
**目标**：系统具备分发给多个研究员并发使用的隔离能力，并配置稳定的线上部署环境。

1. **会话与用户认证 (Auth)**：
   - 引入 JWT，重构 API 鉴权。
   - 升级 `Delivery` 管线的 `SessionManager`，让所有 Redis 数据、上传文档、及 `.xiaoye_memory` 数据带有租户 ID (Tenant_ID) 前缀隔离。
2. **日志与审计**：
   - 完善全局异常捕获，建立针对 Tool 调用、LLM 请求的耗时及 Token 消耗监控日志。
3. **Docker Compose 流水线**：
   - 将现有零散的 `start_server.sh` 淘汰，提供完整的 `docker-compose.yml` 编排。
   - 引入 Nginx 反向代理层，支持 HTTPS 和 WSS（如果引入 WebSocket），配置 Redis 和 Postgres 的生产级安全策略。
